# Persistent World: build, assets and operations

The spatial world runs at `/TRPG/`; the legacy text experience is retained at `/TRPG/legacy.html`. The world API is `/TRPG/api/world`. Babylon.js core/loaders are pinned together at 9.25.0 and esbuild produces the browser modules. Use Node 22 and `npm ci`, then `npm run world:check`. `npm run world:serve` starts the isolated local world server on port 3100; `npm start` starts the existing combined application.

## Content and save compatibility

Authoritative content is `src/server/trpg/world/content/world-content.json`. It is never copied into `public/`. The session endpoint selects public catalog fields, and simulation projection controls which nearby entities and known events a player receives. NPC private beliefs, event causes and hidden resolution conditions belong on the server.

Every save records a schema version, content revision and SHA-256 of the parsed content. Both revision and hash must match before an existing save can advance. Editing content while retaining the same revision is therefore rejected too. Older saves that predate the content hash need an explicitly reviewed migration. There is no automatic migration or silent reset. `newGame: true` is the explicit replacement operation. Before content releases, archive both the old content and saves; either implement and test a versioned migration or continue serving the matching release. Art replacement alone does not alter saves.

## Storage and shutdown

This adapter is for **one Node writer using a durable local disk**. Set `TRPG_WORLD_SAVE_DIRECTORY` to an absolute directory on a persistent volume outside the release folder. The default `runtime-data/TRPG/world-saves` is convenient locally; an ephemeral hosting filesystem is unsuitable. Keep a single application replica and disable overlapping rolling deployments. This adapter has no cross-process lease or distributed transaction: multiple processes sharing one directory can overwrite each other's authority. Horizontal deployment requires replacing it with a database adapter with owner-level compare-and-swap and leasing, not just adding sticky sessions.

Commands are serialized per owner and validated on a candidate state. A successful response follows durable write, with the sequence and receipt stored in the same record. Writes create a private temporary file, fsync it, and atomically rename it; Linux also fsyncs the directory entry. Windows cannot fsync directories through this Node implementation. If a write reports an uncertain outcome after rename, the cached world is evicted and the next request reloads its durable receipt so a retry cannot charge twice. Back up the directory and matching content as one release set; test restoration before depending on it. Cookies are bearer resume credentials, scoped to `/TRPG`, HttpOnly and SameSite=Lax. Clearing the cookie loses browser access to that world; account linking/recovery is not implemented.

`SIGTERM` and `SIGINT` stop the HTTP listener, reject new world operations, drain previously admitted commands (including in-progress creation), advance and save every loaded world, and close sockets. Failure exits nonzero. The deadline is 25 seconds; configure the process manager's termination grace period above that. Do not use `SIGKILL` for normal releases. Background clock changes are checkpointed every five seconds; accepted commands are saved before acknowledgment. Offline catch-up is performed by the server simulation on resume and held movement inputs are cleared.

## Asset provenance and replacement

The deployable art is under `public/TRPG/world/assets`. `manifest.json` records each file's hash, byte size, original source path/hash, source archive hash, creator, package version and license. The current packs are [Fantasy Town Kit](https://kenney.nl/assets/fantasy-town-kit), [Blocky Characters](https://kenney.nl/assets/blocky-characters), [Cube Pets](https://kenney.nl/assets/cube-pets), and [Prototype Kit](https://kenney.nl/assets/prototype-kit), all CC0. Their supplied license files remain beside the models. Prototype pack geometry is temporary art that can be replaced through the semantic asset mapping.

Original archives and extracted directories are kept outside the repository, in the workspace `asset-sources` folder. `npm run world:assets:import -- /absolute/path/to/asset-sources` compares deployed file bytes with the extracted originals and records archive fingerprints. This is a deliberate import/approval step, not something CI silently regenerates. Review the source, license and visual result when changing a pack, copy the selected GLB and texture dependencies, then run this command and inspect the manifest diff. It does not download or trust a later upstream release automatically. Custom Blender exports require their own documented provenance and extension to the importer rather than inventing Kenney source matches.

`npm run world:assets:check` verifies the committed file inventory and hashes, GLB headers/chunks/buffers, animation names, and image/buffer URI resolution. It rejects remote URIs, directory escapes, missing textures and unrecorded edits. This structural inspection is not a full glTF validator or a visual test. It reports mesh, primitive, skin, material and animation counts for art review. The current library includes animated characters and creatures; the game maps animation names such as `idle`, `walk` and `attack-melee-right` in its asset runtime. After replacement, play-test size, foot placement, collision fit, material appearance, shadowing and all used animation states in the browser.

## Browser build and release

`world:build` compiles in memory, applies bundle budgets and publishes chunks before the entry and HTML. A compile error cannot delete the working bundle. Hashed chunks are kept during development builds so already-open tabs can load their dependencies. Babylon's lazy shader and loader modules can generate many small chunks; `tools/trpg-world/reports/build.json` distinguishes the initial static graph from lazy files and reports raw/gzip byte counts and hashes. Gzip counts are estimates; configure actual HTTP compression in the production reverse proxy. The reviewed limits are 12 MiB total raw JavaScript and 2 MiB initial gzip, not a guarantee of acceptable frame rate on every device.

Deploy immutable release directories with the complete new assets, generated bundle and matching server content, then switch the release only after stopping the old writer. Retain older static release chunks for clients with old tabs where applicable. Give HTML and `client.js` revalidation caching; only hashed chunks are eligible for immutable caching. Do not perform a build in a live shared release directory or delete chunk files while old pages use them. The new CI workflow runs content validation, asset verification, authority/simulation tests and the browser build without contacting Sheets or legacy route ledgers. Browser play-testing remains an additional release requirement.
