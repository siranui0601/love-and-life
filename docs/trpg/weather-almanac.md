# 天候年鑑

> **担当者の指示（2026-08-13）**
> 「天候は、シード値で任意にするのではなく、既存のデータとして残すようにしましょう。
> この地域ではこの日は１日中晴れ、この地域では15時から大雨　等、地域性も考慮しつつ、
> 一意性を保ちながら一定の天気となるようにしましょう。」

---

## 以前は何だったか

`weather-resolver.js` は「シードに依存しない」と書いてあり、それ自体は本当だった。
だが**中身は確率抽選**で、しかも**朝・昼・夕・夜を独立に引いていた。**

```js
const roll = stableHash32(scheduleKey) / 0x100000000;
const weatherId = weightedPick(weightedEntries(profile, normalizedDaypart), roll);
```

この作りには二つ問題があった。

### 一日が繋がっていなかった

朝・昼・夕・夜が別々の籤なので、**朝は快晴、昼は雷雨、夕は霧、夜は快晴**という日が普通に出る。
天気は連続した現象であって、四回の独立試行ではない。

### そして、その籤は分布していなかった

`stableHash32` は FNV-1a である。**末尾が一文字違うだけの入力に対して、ほぼ連続した値を返す。**
北陵要塞のDay71〜100を実際に並べると：

```
0.617 0.621 0.625 0.629 0.633 0.637 0.641 0.645 0.649 0.716 0.712 ...
```

**三十日ぶんの「乱数」が 0.6〜0.7 に固まっている。**
だから同じ土地では何日も同じ天気が続き、重み表の下の方にある天気は**一度も出なかった。**
北陵要塞の晩秋に雪が降らなかったのは、雪の重みが足りなかったからではなく、
**籤がそこまで届いていなかったから**である。

（この `stableHash32` は `authored-weather-ambient-continuity.js` の場面IDにも使われている。
そちらは別途の話だが、同じ性質を抱えている。）

## いま何か

**`src/server/trpg/content/weather-almanac.js` に、全1200日ぶんの空が書いてある。**
12地域 × 100日。抽選はもう無い。

```js
"田園の村": Object.freeze([
  /* Day  6〜 10 */ "cloudy;15=light_rain;18=cloudy", "clear", "clear;19=storm;20=cloudy", ...
```

### 一日の書き方

| 書き方 | 意味 |
|---|---|
| `clear` | 00:00 から**一日中 晴れ** |
| `cloudy;15=rain` | 曇り。**15:00 から雨** |
| `fog;08=clear` | 朝霧。**08:00 に晴れる** |
| `cloudy;13=storm;19=rain;22=cloudy` | 曇り→13:00 雷雨→19:00 雨→22:00 曇り |

区切りは 00:00 から始まり、次の区切りまで同じ天気が続く。
**時刻は必ず増え、隣り合う区切りは必ず違う天気になる。**（`weather-resolver.test.mjs` が全1200日を検算）

**直したい日があれば、その行を書き換える。それが唯一の直し方である。**

## 地域性

| 地域 | 気候 | 実測（延べ時間） |
|---|---|---|
| 田園の村 | 晴れが多い。盛夏の夕立 | 晴49% 曇35% 小雨6% |
| 辺境の村 | **乾いた風。**雨が少ない | 晴40% 曇37% **乾いた風15%** |
| 王都 | 曇りがち。秋の雨 | 曇45% 晴38% 雨10% |
| 森 | **朝霧。**降ると長い | 曇46% 晴17% **霧16%** 雨15% |
| エルフの隠れ里 | 森と同じ系統。より霧が濃い | 曇47% 晴23% 霧16% |
| 交易都市 | **海風。**前線が一番早く来る | 曇48% 晴24% 雨13% **強風12%** |
| 犯罪都市 | **霧雨と曇り。**晴れ間が少ない | **曇60%** 晴27% 小雨8% |
| ドワーフ洞窟 | 坑口の霧 | 曇49% **霧22%** 雨14% |
| 北陵要塞 | **晩秋は雪。**Day71〜100の三十日中十九日が雪絡み | 曇43% 晴26% **雪13%** |
| 古代神殿 | 霧の多い高地 | 曇57% 晴18% 霧15% |
| 黒嶺連合領 | 風。雨も来る | 曇41% 晴32% 雨15% |
| 魔王領 | **砂の風** | 曇49% **乾いた風21%** 晴20% |

**田園の村には雪が一日も降らない。北陵要塞には必ず降る。**これも検算している。

### 天気は移動する

同じ日は全土がおおむね同じ気圧配置を受けるが、**雨の来る時刻が土地ごとにずれる。**
交易都市が一番早く、魔王領が一番遅い。

| 地域 | 前線の到達差 |
|---|---:|
| 交易都市 | **−3時間** |
| 犯罪都市・辺境の村 | −2時間 |
| 王都・古代神殿 | 0 |
| 田園の村 | +1時間 |
| 森・エルフの隠れ里 | +2時間 |
| ドワーフ洞窟・黒嶺連合領 | +3時間 |
| 北陵要塞 | +4時間 |
| 魔王領 | **+5時間** |

だから**「王都で昼から降った日は、森では夕方から降る」。**
一日の型が同じでも、**時刻がずれれば別の一日である。**各地39〜60通りの一日がある。

## 一本道との噛み合い

書き上げた討伐ルートDay8〜Day21に、年鑑を重ねた。**書き直しは要らず、むしろ噛み合った。**

| 日 | 場面 | 年鑑 |
|---|---|---|
| **Day8** | 21:00 柵の崩れ目・赤牙狼と戦う | 田園の村 晴れ→**19:00 雷雨**→20:00 曇り。**二時間前まで雷雨だった夜に戦う** |
| Day9 | 朝、幼体を狩る | 田園の村 曇り→15:00 小雨。**朝のうちなら濡れない** |
| Day14 | 農具鉈を下取り、薪割り斧を買う | 田園の村 **終日 晴れ。**武器の無い一日が晴れている |
| Day15 | 05:00 出発、07:00 王都通過、13:00 森着 | 王都 晴れ→**10:00 強風**。**三時間早く抜けている** |
| **Day16** | 06:00 猟師が川の水量を語る | 森 **霧**→13:00 曇り。**朝霧の中で聞く** |
| **Day17** | 09:40 小型キングスライム | 森 **終日 曇り。**窓の最終日は、晴れも降りもしない |
| **Day20** | 15:00 群れ親＋赤牙狼×2 | 田園の村 **終日 晴れ。**主要期限の当日だけ、空が開いている |

**Day8の雷雨は書いていなかったが、書いてあった。**
年鑑が先にあれば、場面の側がそれを拾える。**これが「データとして残す」の効きどころである。**

## 使い方

```js
import { resolveCanonicalWeather, resolveCanonicalWeatherAt, canonicalWeatherSegments }
  from "src/server/trpg/resolvers/weather-resolver.js";

resolveCanonicalWeather({ day: 8, regionId: "田園の村", daypart: "night" });   // 既存の呼び口
resolveCanonicalWeatherAt({ day: 8, regionId: "田園の村", hour: 21 });          // 時刻で引く（新）
canonicalWeatherSegments({ day: 8, regionId: "田園の村" });                     // その日の全区切り（新）
```

`resolveCanonicalWeather` の署名は変えていない。**四つの時間帯は、書かれた一日から抜き出す**形になった
（morning=07:00／afternoon=13:00／evening=19:00／night=23:00）。

**スプレッドシート用の全1200行は `docs/trpg/weather-almanac.csv`。**
時刻ごとの天気と「15:00から雨」といった変化を日本語で展開してある。

## 残していること

- **`WEATHER_RULESET_VERSION` を `canonical-weather-almanac-v2` に上げた。**
  保存済みのセーブが持つ天候は、この版から作り直される
- **`playerState.weather` は、場面文の選択には使われていない。**
  `authoredSceneContext` が年鑑を直接引いている。
  検査 `authored-journey-presentation.test.mjs` はこれに気づかず `playerState.weather` を
  手で雨に差し替えて通っていた（旧ハッシュがたまたま雨を出していただけ）。
  **年鑑で本当に雨の日（王都Day26）を使うよう直した**ので、いまは意図通りの検査になっている
- **天候の場面IDの重複問題は別件。**`authored-weather-ambient-continuity.js` が
  同じ報せを見送られても再提示し続ける件は、この作業では触れていない
